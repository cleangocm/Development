Overview

UltraWash is a complete, production-ready laundry service booking platform built with modern technologies. It provides a seamless experience for Customers, Delivery Boys, Staff, and Admins — each with dedicated dashboards, real-time notifications, and role-based access control.


The application follows a decoupled architecture: a Next.js 16 frontend communicates with an Express.js 5 REST API backend powered by MongoDB. This separation ensures scalability, maintainability, and easy deployment.

Sign Up & Log In

3 easy ways ▶

Customers can create an account and sign in using whichever method is most convenient for them. All login methods give access to the same customer dashboard.

Option 1 — Email & Password

  • Customer goes to the Sign Up page and enters their full name, phone number, email address, and a password.
  • All fields are checked as the customer types — clear error messages appear instantly if something is wrong (e.g. password too short, email format invalid).
  • Once registered, the customer logs in with their email (or phone) and password.
  • Sessions are remembered automatically. If they close the browser and return, they stay logged in. If the session expires, they are taken back to the login page.

Option 2 — Sign in with Google

  • Customer clicks "Continue with Google" on the login or sign-up page.
  • A Google account picker opens. The customer selects their account — no password needed.
  • If this is their first time, an account is created automatically using their Google name and profile picture.
  • Their Google profile photo appears in their dashboard and throughout the app.

Option 3 — One-Time Code (OTP)

  • Customer enters their phone number or email address and requests a 6-digit code.
  • The code is sent instantly via SMS (to their phone) or email.
  • They enter the code to log in — no password required at all.
  • The code expires after 10 minutes for security.

Forgot Password

  • Customer clicks "Forgot password?", enters their email, and receives a reset link.
  • Clicking the link takes them to a page where they set a new password.
Pages: Sign Up  |  Log In  |  OTP Verification  |  Forgot Password  |  Create New Password

Browse Services

All services ▶

Customers can browse all available laundry services with photos, clear descriptions, and transparent pricing — before placing any order.

What customers see

  • The Services page shows all active services as cards with a photo, name, starting price, and category badge.
  • Clicking a service opens its detail page — showing all sub-items, pricing per kg or per item (e.g. jeans: $3.00, suit: $8.00), and a full description.
  • Services are organised by category: Wash & Fold, Dry Cleaning, Ironing, Premium Wash, Bedding & Linen, Shoe Cleaning, and more.
  • Popular or top-selling services show a Best Seller badge automatically.
  • Customers can add items directly to their cart from any service detail page.

Managing services (Admin)

  • Go to the Admin Panel → Services to add, edit, or remove services.
  • For each service, set the name, description, category, starting price, and upload a photo.
  • Add individual items with their own prices (e.g. T-Shirt: $2.00, Jacket: $6.00).
  • Changes appear on the public services page immediately after saving.
Pages: Services  |  Service Detail  |  Admin → Services

Shopping Cart

Auto-saved ▶

Customers build their order in the cart before checking out. The cart is saved automatically — even if they close the browser and come back later, their items are still there.

  • From any service page, customers choose items (or enter a weight in kg) and click Add to Cart.
  • The cart icon in the top navigation shows a live count of how many items are in the cart.
  • On the Cart page, customers can increase or decrease quantities, remove individual items, or empty the entire cart.
  • There is a Coupon Code field — entering a valid code immediately shows the discount and updates the total.
  • The price summary clearly shows: Subtotal, Delivery Charge, Discount (if any), and the final Total.
  • Clicking Proceed to Checkout takes the customer to the checkout page with all cart items preserved.
Page: Cart

Pickup & Delivery Scheduling

Choose your dates ▶

At checkout, customers choose when they want their laundry picked up and when they’d like it delivered back — completely flexible and transparent.

  • Pickup Date — A calendar lets customers select any date from tomorrow onwards.
  • Delivery Speed — Three options to suit different budgets and urgency:
      • Standard — No extra charge, returned in 4 or more days
      • Fast — Small extra fee, returned in 2 days
      • Premium — Returned the very next day
  • Delivery Date — The earliest available return date is automatically calculated and shown based on the chosen speed.
  • Customers cannot accidentally choose a past date — the calendar prevents it.
  • The chosen pickup and delivery dates are shown throughout the order journey — on the customer’s dashboard, the admin panel, and the delivery app.
Page: Checkout — Scheduling section

Coupon & Discount System

Percentage & Fixed ▶

Customers can save money with discount coupons at checkout. Admins create and manage all coupon codes from the admin panel.

How customers use coupons

  • Customers can browse available coupons from their Dashboard → My Coupons page.
  • On the Cart or Checkout page, they enter a coupon code and click Apply.
  • If the code is valid, the discount appears instantly in the price summary.
  • The coupon is only counted as “used” once the order is successfully placed — not when the code is entered.

How admins manage coupons

  • Go to Admin Panel → Coupons and click Create Coupon.
  • Set the coupon code (e.g. SAVE20), discount type (percentage off or fixed amount off), discount value, minimum order amount, usage limits, and active dates.
  • Coupons can have a maximum number of total uses and a per-customer limit.
  • Expired or fully-used coupons are automatically deactivated — customers cannot use them.
  • Ready-made demo coupons are included to test the feature out of the box.
Pages: Cart  |  Dashboard → My Coupons  |  Admin → Coupons

Reviews & Ratings

After delivery only ▶

Customers can rate and review the service after receiving their laundry. Only verified, completed orders can be reviewed — keeping all feedback genuine and trustworthy.

How customers leave a review

  • Once an order is marked as Delivered, a “Write a Review” button appears on that order’s detail page.
  • The customer picks a star rating (1 to 5) and writes a short comment about their experience.
  • The review is submitted and waits for admin approval before appearing publicly on the website.
  • Customers can view, edit, or delete their own reviews from Dashboard → My Reviews.

How admins manage reviews

  • All new reviews appear in Admin Panel → Reviews waiting for approval.
  • Admin can Approve a review to make it publicly visible, write a public Reply, or Delete it.
  • Approved reviews are shown on the homepage testimonials section and contribute to the overall star rating.
Pages: Dashboard → My Reviews  |  Admin → Reviews

Help & Support Tickets

Built-in helpdesk ▶

No need for a third-party support tool. Customers can raise issues directly inside the app and chat with the support team until their problem is resolved.

How customers get help

  • From Dashboard → Support, click New Ticket.
  • Enter a subject, choose a category (e.g. Order Issue, Payment Problem, General Inquiry), set a priority, and describe the issue.
  • Once submitted, the ticket appears in the customer’s ticket list with a status badge (Open, In Progress, Resolved, Closed).
  • Clicking any ticket opens a threaded chat view — customers and admins can exchange messages back and forth.
  • Customers get notified (in-app and by email) whenever the admin replies or changes the ticket status.

How admins handle tickets

  • All tickets appear in Admin Panel → Tickets, filterable by status: All, Open, In Progress, Resolved, Closed.
  • Admins can assign tickets to team members, update priority, change status, and reply directly in the ticket thread.
  • New ticket notifications are sent to the admin instantly.
Pages: Dashboard → Support  |  Admin → Tickets

Delivery Staff App

Pickup & drop-off ▶

Delivery staff have their own dedicated login and app view — completely separate from the customer area. Everything they need for daily pickups and deliveries is in one place.

Dashboard overview

  • When they log in, delivery staff see today’s summary: assigned pickups, assigned deliveries, how many they’ve completed today, and their pending earnings.

Pickup workflow

  • The Assigned Pickups list shows each customer’s name, address, phone, and order details.
  • When the delivery person arrives and collects the laundry, they tap Confirm Pickup. The order status updates so the customer and admin can see it has been collected.
  • They then bring it to the warehouse and confirm arrival.

Delivery workflow

  • Once cleaning is complete, the admin assigns the delivery. The delivery person sees it in their Out for Delivery list.
  • They mark Start Delivery when heading out, then Confirm Delivered when the laundry is handed to the customer.
  • The completed delivery is added to their history with earnings recorded.

Navigation & Earnings

  • A Get Directions button opens Google Maps navigation to the customer’s address from their current location.
  • Earnings accumulate with each completed pickup and delivery. The admin settles earnings from the admin panel.
Access: Delivery Login  |  Delivery Dashboard

Cleaning Staff Panel

Laundry management ▶

The cleaning team has their own separate login and a simple, focused panel showing exactly what they need to clean each day.

  • After logging in, staff see their dashboard with a count of orders assigned to them, orders currently being cleaned, and how many they’ve completed today.
  • The Orders page has three tabs: Assigned (arrived at warehouse, ready to clean), In Progress (currently being cleaned), and Completed (done).
  • For each Assigned order, staff can see the customer name, items to be cleaned, and any special instructions left by the customer.
  • Click Start Cleaning to begin — the order moves to the In Progress tab so the admin knows it’s being worked on.
  • Click Mark as Cleaned when done. A notes box lets staff add remarks (e.g. “Extra stain treatment applied to shirt”).
  • Once marked cleaned, the admin is notified and can assign a delivery person to return the laundry.
Access: Staff Login  |  Staff Dashboard  |  Staff Orders

Refund Management

Card & Cash orders ▶

Admins can issue full or partial refunds from inside the app — no need to log into Stripe separately for card payments.

  • Go to Admin Panel → Payments. Each payment shows its status: Paid, Pending, Refunded, or Partially Refunded.
  • Click Issue Refund on a paid order. Enter the refund amount (defaults to the full order amount), a reason, and any internal notes.
  • For card payments (Stripe): the refund is processed automatically and the money returns to the customer’s card within 5–10 business days. No manual steps needed.
  • For Cash on Delivery orders: the refund is recorded in the system as a reference. The physical cash is returned to the customer separately.
  • The order payment status updates automatically, and the complete refund history is shown in the payment detail view.
  • The customer receives an email notification when a refund is issued.
Page: Admin → Payments

Secure Access & Role Permissions

Role-based ▶

Every account is protected and each user role can only access the pages and features relevant to them — nobody can accidentally (or intentionally) access the wrong section.

  • When someone logs in, the system issues a secure access token that lasts 7 days. All actions they take are authenticated with this token.
  • The token is stored safely in the browser. If it expires or is invalid, the user is automatically sent back to the login page.
  • Role-based access: a Customer logging in can only see their own dashboard. A delivery staff member can only see the delivery app. Staff members can only see the cleaning panel. Only admins can access the admin panel.
  • If someone tries to access a page they’re not allowed to view (e.g. a customer trying to reach the admin panel), they are redirected away immediately.
  • When a session times out or the browser is closed for too long, the user is quietly signed out for security.
⚠
Important: Before going live, set a unique, random secret key in your backend settings file. This key protects all user sessions — keep it private and never share it.

Cloud Database Ready

Local or cloud ▶

UltraWash works with both a local database (on your own computer) and a cloud-hosted database — switching between them takes one line change.

  • All database tables (orders, users, services, stores, etc.) are created automatically when the app starts for the first time. No manual setup or database scripts needed.
  • The Find Nearest Store feature uses location-based database queries to return branches closest to a customer’s GPS coordinates.
  • Reports and analytics are powered by fast database-level calculations rather than loading all records and calculating in the app.
  • For cloud hosting, the free tier of MongoDB Atlas gives you up to 512 MB of storage — more than enough for a full laundry business with thousands of orders.

Switching to cloud database

  • Sign up for a free MongoDB Atlas account at mongodb.com/atlas.
  • Copy your connection string from Atlas and replace the local database address in the backend settings file.
  • Restart the backend — no other changes needed.

Easy Deployment

Vercel + Render ▶

The frontend and backend are separate projects, making deployment simple and flexible. Both can be hosted for free using popular platforms.

Deploy the frontend (website) → Vercel (free)

  • Push the frontend code to a GitHub repository.
  • Go to vercel.com → click New Project → import your repository.
  • Add your environment settings (API URL, Stripe key, Google Maps key, etc.) in the Vercel project settings.
  • Click Deploy. Vercel builds and publishes the site. Every time you push a code update to GitHub, it re-deploys automatically.

Deploy the backend (API) → Render (free)

  • Push the backend code to a separate GitHub repository.
  • Go to render.com → click New Web Service → connect the repo.
  • Add all backend settings (database URL, email key, Stripe secret, etc.) in Render’s dashboard.
  • Use MongoDB Atlas (cloud database) instead of a local database when hosting on Render.
⚠
Security note: Before going live, update the allowed origins in the backend to only accept requests from your deployed frontend website address.

Test on Phone & Tablet (Same Wi-Fi)

No setup needed ▶

You can open and test the app on your phone or tablet from the same Wi-Fi network while it’s running on your computer — no extra configuration needed.

  • Start the frontend on your computer as usual.

Reliable & Graceful Error Handling

Smart recovery ▶

The app handles connection problems and server errors gracefully — users always see a helpful, friendly message instead of a broken page or confusing error code.

  • Every request to the server automatically includes the user’s login token — so they never need to worry about re-authenticating on each page.
  • If the login session expires, the user is quietly redirected to the login page — no broken pages or confusing blank screens.
  • If the server is temporarily unavailable or returns an error, the app shows a clear, friendly error page explaining what happened.
  • All requests have a 15-second timeout. If the server doesn’t respond in time (e.g. internet drops), the app handles it gracefully and shows an appropriate message.
  • Minor errors (like a failed form submission) are shown as toast pop-up messages without disrupting the rest of the page.

Quick Start

Purchased from CodeCanyon? — Download the zip from your Envato Downloads page, then follow the steps below. No git required.
Make sure MongoDB is running locally on port 27017, or use a MongoDB Atlas connection string.

Download & Extract from CodeCanyon

Log in to codecanyon.net/downloads, find UltraWash and click Download → All files & documentation. You will receive a .zip archive.

Extract the archive. The folder structure inside looks like this: 

ultrawash/
├── backend/        ← Express.js API server
├── frontend/       ← Next.js frontend (this project)
└── documentation/ ← documentation.html & guides

Open a terminal and cd into the extracted folder: 

cd ultrawash

Install Backend Dependencies

cd backend
npm install

Configure Backend Environment

Duplicate the example file and fill in your credentials: 

# Windows (Command Prompt)
copy .env.example .env

# Mac / Linux
cp .env.example .env

Open .env in any text editor and set your MONGODB_URI, JWT_SECRET, STRIPE_SECRET_KEY, etc. See the Environment Variables section for the full list.

Start Backend Server

npm run dev
# Server runs on http://localhost:3000

On first run the backend auto-creates the MongoDB database, collections, and default admin / delivery / staff accounts.

Install Frontend Dependencies

Open a second terminal (keep the backend running), then: 

cd frontend
npm install

Configure Frontend Environment (optional for local dev)

Create .env.local inside the frontend/ folder: 

NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY=pk_test_xxxxxxxxxxxx
NEXT_PUBLIC_FIREBASE_API_KEY=your-firebase-api-key
NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN=your-project.firebaseapp.com
NEXT_PUBLIC_FIREBASE_PROJECT_ID=your-project-id
NEXT_PUBLIC_GOOGLE_MAPS_API_KEY=your-google-maps-key
💡
For local testing without .env.local, the app still runs — Google login, Stripe payments and Maps will simply be inactive until the keys are added.

Start Frontend Dev Server

npx next dev -p 3001
# App opens at http://localhost:3001

Seed Demo Data

Run this once from the frontend/ folder to populate sample coupon codes: 

node seed-coupons.mjs
# Creates SAVE20, WELCOME50, FLAT100 and more in your database
✅
All done! — Visit http://localhost:3001 for the storefront and http://localhost:3001/admin/login for the admin panel. Use the demo accounts to log in immediately.

Frontend Setup

Key Configuration

The frontend auto-detects the backend URL. If accessing from another device on the same network, it uses the device's LAN IP.

// src/services/api.ts
const baseURL = typeof window !== 'undefined'
  ? \`http://\${window.location.hostname}:3000/api/v1\`
  : 'https://laundry-service-booking-app-backend.onrender.com/api/v1';

// Axios instance with JWT interceptor
const api = axios.create({ baseURL, timeout: 15000 });
api.interceptors.request.use(config => {
  const token = localStorage.getItem('token');
  if (token) config.headers.Authorization = \`Bearer \${token}\`;
  return config;
});

Flutter Setup

Flutter Mobile App

A Flutter version of UltraWash is included in the purchase, sharing the same backend API as the web app — so you can launch on both iOS and Android with a native mobile experience.

  • The mobile app code is located in the Mobile App/ folder of the downloaded package.
  • It uses the same backend API as the web app, so all features (orders, payments, notifications, etc.) work seamlessly.
  • The mobile app is built with Flutter for easy development and deployment to app stores.

System Requirements

  • Flutter SDK — Install Flutter (stable channel)
  • Android Studio or VS Code
  • Xcode (macOS only, required for iOS builds)
  • Firebase account for push notifications & Google Sign-In
  • Node.js (for Firebase CLI)

Verify your Flutter installation:

flutter --version
flutter doctor
⚠
Flutter Doctor must show no critical errors before continuing.

Project Setup

Extract the project ZIP

Unzip the downloaded package and open the Mobile App/ folder in Android Studio or VS Code.

Install dependencies

Option 1: Open pubspec.yaml in your IDE and click Pub get.

Option 2: Run the following command in your terminal:

flutter pub get

Run the app

flutter run

dart run flutter_launcher_icons

To point the mobile app to your own backend, update the baseUrl variable in lib/core/service/api_service.dart. 

// lib/core/service/api_service.dart
static const String baseUrl = 'https://your-domain.com/api/v1';

Firebase Setup

1. Go to Firebase Console
2. Create project → Enable Authentication → Google Sign-In
3. Add web app → Copy config to .env.local
4. Download service account JSON → Base64 encode → Add to backend .env

📸

ImgBB Setup

1. Register at api.imgbb.com
2. Get your free API key
3. Add IMGBB_API_KEY to backend .env

📧

Brevo SMTP Setup

1. Create account at brevo.com
2. Go to SMTP & API → Get API Key
3. Add BREVO_API_KEY and sender email to backend .env

📍

Google Maps Setup

1. Go to Google Cloud Console
2. Enable Maps JavaScript API & Geocoding API
3. Create API key → Restrict to your domain
4. Add to NEXT_PUBLIC_GOOGLE_MAPS_API_KEY

Twilio SMS (Optional)

1. Sign up at twilio.com
2. Get Account SID, Auth Token & Phone Number
3. Add to backend .env (TWILIO_ACCOUNT_SID, etc.)
