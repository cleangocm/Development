Overview

UltraWash is a complete, production-ready laundry service booking platform built with modern technologies. It provides a seamless experience for Customers, Delivery Boys, Staff, and Admins — each with dedicated dashboards, real-time notifications, and role-based access control.


The application follows a decoupled architecture: a Next.js 16 frontend communicates with an Express.js 5 REST API backend powered by MongoDB. This separation ensures scalability, maintainability, and easy deployment.

💡
Base API: https://laundry-service-booking-app-backend.onrender.com/api/v1  |  Admin Panel: https://laundry-service-booking-app-backend.onrender.com/api/v1

Sign Up & Log In

3 easy ways ▶

Customers can create an account and sign in using whichever method is most convenient for them. All login methods give access to the same customer dashboard.

Option 1 — Email & Password

  • Customer goes to the Sign Up page and enters their full name, phone number, email address, and a password.
  • All fields are checked as the customer types — clear error messages appear instantly if something is wrong (e.g. password too short, email format invalid).
  • Once registered, the customer logs in with their email (or phone) and password.
  • Sessions are remembered automatically. If they close the browser and return, they stay logged in. If the session expires, they are taken back to the login page.

Option 2 — Sign in with Google

  • Customer clicks "Continue with Google" on the login or sign-up page.
  • A Google account picker opens. The customer selects their account — no password needed.
  • If this is their first time, an account is created automatically using their Google name and profile picture.
  • Their Google profile photo appears in their dashboard and throughout the app.

Option 3 — One-Time Code (OTP)

  • Customer enters their phone number or email address and requests a 6-digit code.
  • The code is sent instantly via SMS (to their phone) or email.
  • They enter the code to log in — no password required at all.
  • The code expires after 10 minutes for security.

Forgot Password

  • Customer clicks "Forgot password?", enters their email, and receives a reset link.
  • Clicking the link takes them to a page where they set a new password.

Coupon & Discount System

Percentage & Fixed ▶

Customers can save money with discount coupons at checkout. Admins create and manage all coupon codes from the admin panel.

How customers use coupons

  • Customers can browse available coupons from their Dashboard → My Coupons page.
  • On the Cart or Checkout page, they enter a coupon code and click Apply.
  • If the code is valid, the discount appears instantly in the price summary.
  • The coupon is only counted as “used” once the order is successfully placed — not when the code is entered.

How admins manage coupons

  • Go to Admin Panel → Coupons and click Create Coupon.
  • Set the coupon code (e.g. SAVE20), discount type (percentage off or fixed amount off), discount value, minimum order amount, usage limits, and active dates.
  • Coupons can have a maximum number of total uses and a per-customer limit.
  • Expired or fully-used coupons are automatically deactivated — customers cannot use them.
  • Ready-made demo coupons are included to test the feature out of the box.

Refund Management

Card & Cash orders ▶

Admins can issue full or partial refunds from inside the app — no need to log into Stripe separately for card payments.

  • Go to Admin Panel → Payments. Each payment shows its status: Paid, Pending, Refunded, or Partially Refunded.
  • Click Issue Refund on a paid order. Enter the refund amount (defaults to the full order amount), a reason, and any internal notes.

  • The order payment status updates automatically, and the complete refund history is shown in the payment detail view.
  • The customer receives an email notification when a refund is issued.

Secure Access & Role Permissions

Role-based ▶

Every account is protected and each user role can only access the pages and features relevant to them — nobody can accidentally (or intentionally) access the wrong section.

  • When someone logs in, the system issues a secure access token that lasts 7 days. All actions they take are authenticated with this token.
  • The token is stored safely in the browser. If it expires or is invalid, the user is automatically sent back to the login page.
  • Role-based access: a Customer logging in can only see their own dashboard. A delivery staff member can only see the delivery app. Staff members can only see the cleaning panel. Only admins can access the admin panel.
  • If someone tries to access a page they’re not allowed to view (e.g. a customer trying to reach the admin panel), they are redirected away immediately.
  • When a session times out or the browser is closed for too long, the user is quietly signed out for security.
⚠
Important: Before going live, set a unique, random secret key in your backend settings file. This key protects all user sessions — keep it private and never share it.

Cloud Database Ready

Local or cloud ▶

UltraWash works with both a local database (on your own computer) and a cloud-hosted database — switching between them takes one line change.

  • All database tables (orders, users, services, stores, etc.) are created automatically when the app starts for the first time. No manual setup or database scripts needed.
  • The Find Nearest Store feature uses location-based database queries to return branches closest to a customer’s GPS coordinates.
  • Reports and analytics are powered by fast database-level calculations rather than loading all records and calculating in the app.
  • For cloud hosting, the free tier of MongoDB Atlas gives you up to 512 MB of storage — more than enough for a full laundry business with thousands of orders.

Switching to cloud database

  • Sign up for a free MongoDB Atlas account at mongodb.com/atlas.
  • Copy your connection string from Atlas and replace the local database address in the backend settings file.
  • Restart the backend — no other changes needed.

Easy Deployment

Vercel + Render ▶

The frontend and backend are separate projects, making deployment simple and flexible. Both can be hosted for free using popular platforms.

Deploy the frontend (website) → Vercel (free)

  • Push the frontend code to a GitHub repository.
  • Go to vercel.com → click New Project → import your repository.
  • Add your environment settings (only NEXT_PUBLIC_API_URL and optionally NEXT_PUBLIC_GOOGLE_MAPS_API_KEY) in the Vercel project settings. All payment keys are managed from the Admin Panel — no Stripe key needed here.
  • Click Deploy. Vercel builds and publishes the site. Every time you push a code update to GitHub, it re-deploys automatically.

Deploy the backend (API) → Render (free)

  • Push the backend code to a separate GitHub repository.
  • Go to render.com → click New Web Service → connect the repo.
  • Add all backend settings (database URL, email key, Stripe secret, etc.) in Render’s dashboard.
  • Use MongoDB Atlas (cloud database) instead of a local database when hosting on Render.
⚠
Security note: Before going live, update the allowed origins in the backend to only accept requests from your deployed frontend website address.

Reliable & Graceful Error Handling

Smart recovery ▶

The app handles connection problems and server errors gracefully — users always see a helpful, friendly message instead of a broken page or confusing error code.

  • Every request to the server automatically includes the user’s login token — so they never need to worry about re-authenticating on each page.
  • If the login session expires, the user is quietly redirected to the login page — no broken pages or confusing blank screens.
  • If the server is temporarily unavailable or returns an error, the app shows a clear, friendly error page explaining what happened.
  • All requests have a 15-second timeout. If the server doesn’t respond in time (e.g. internet drops), the app handles it gracefully and shows an appropriate message.
  • Minor errors (like a failed form submission) are shown as toast pop-up messages without disrupting the rest of the page.

Feature Deep Dive

Key Modules
📋

Input Validation Middleware — src/lib/validationMiddleware.ts

A single, framework-agnostic TypeScript module that centralises all client-side form validation. Every form in the app imports from this file instead of re-defining rules locally.

What’s inside

ExportPurposeExample
validators.*Primitive rule functions (required, email, phone, strongPassword, otp, etc.)validators.email()(value) → '' | error
validateField()Run multiple rules on a single field; returns first errorvalidateField(email, [validators.required(), validators.email()])
validateForm()Validate an entire form object against a schemavalidateForm(formData, schemas.signup) → { email: '...' }
isFormValid()Check whether a FormErrors object has zero entriesif (!isFormValid(errors)) return;
schemas.*Pre-built schemas: login, signup, checkout, contact, coupon, service, store, …schemas.checkout
useFormValidation()React hook — tracks errors, touched state; exposes touch(), validateAll(), validateOnChange()Drop-in for any form component

Quick Usage

// 1) Import
import { useFormValidation, schemas } from '@/lib/validationMiddleware';

// 2) Inside your component
const { errors, touched, touch, validateAll } = useFormValidation(schemas.signup, formData);

// 3) Attach to inputs
<input
  onBlur={() => touch('email')}
  onChange={e => { setFormData(p => ({...p, email: e.target.value})); }}
/>
{touched.email && errors.email && <span className="text-red-500">{errors.email}</span>}

// 4) Guard the submit handler
const handleSubmit = (e) => {
  e.preventDefault();
  if (!validateAll()) return;   // stops if any field is invalid
  // proceed with API call ...

CSV Export — React-Idiomatic Pattern

Instead of creating a bare DOM element and calling .click() imperatively, the app uses a hidden anchor ref managed by React: 

// 1. Declare ref & download-URL state
const csvAnchorRef = useRef<HTMLAnchorElement>(null);
const [csvDownload, setCsvDownload] = useState<{url:string;filename:string}|null>(null);

// 2. Trigger the anchor via useEffect whenever the URL is set
useEffect(() => {
  if (csvDownload && csvAnchorRef.current) csvAnchorRef.current.click();
}, [csvDownload]);

// 3. Render a hidden anchor in JSX (React owns it)
<a ref={csvAnchorRef} href={csvDownload?.url} download={csvDownload?.filename}
   onClick={handleCsvAnchorClick} className="hidden" />

// 4. Export button simply builds the blob and sets state
<button onClick={handleExportCSV}>Export CSV</button>
✅
This pattern keeps the anchor inside React’s virtual DOM, avoids stale closures, and properly revokes the Blob URL via onClick={handleCsvAnchorClick}.

Frequently Asked Questions

How do I change the default port?▼
Backend: change PORT in .env. Frontend: run npx next dev -p YOUR_PORT.
Can I use MySQL/PostgreSQL instead of MongoDB?▼
The backend is built with Mongoose ODM for MongoDB. Switching to SQL would require rewriting all models, controllers, and queries. MongoDB is recommended.
How do I add a new laundry service?▼
Login as admin → Go to Services → Click "Add Service" → Fill in name, pricing type, items, and image. Or use the API: POST /api/v1/admin/services.
How does the coupon system work?▼
Admin creates coupons with discount type (percentage/fixed), min order amount, max discount, usage limit, and date range. Customers apply coupon codes at checkout. The system validates against all constraints.
Is Stripe required? Can I use only COD?▼
Yes! COD (Cash on Delivery) works without Stripe. If you don't set Stripe keys, the payment page will only show the COD option.
How do I deploy to production?▼
Frontend: Deploy to Vercel (auto-detects Next.js). Backend: Deploy to Render or Railway. Database: Use MongoDB Atlas. See the Deployment section for full instructions.
Can I add more user roles?▼
Yes. Add the new role to the User model's role enum, create new middleware guards, add routes, and build the frontend panel. The auth system supports any number of roles.
How do I handle image uploads?▼
Images are uploaded to ImgBB via POST /api/v1/upload/imgbb (multipart/form-data). The returned URL is stored in the database. Get a free API key from imgbb.com.
